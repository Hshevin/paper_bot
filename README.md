# Paper Bot · AstrBot 论文订阅插件

为每个 QQ 群聊或私聊指定研究方向和检查间隔，自动从 arXiv 收集论文、调用你在 AstrBot 中配置的模型评估相关性，并推送摘要、推荐理由、原文依据和论文链接。所有设置都可在 **AstrBot WebUI → 插件 → Paper Bot → 配置** 中修改，无需编辑 Python 或 JSON。

例如：A 群关注 RAG，每 60 分钟检查；B 群关注机器人规划，每 180 分钟检查；你的私聊订阅两个方向。同一个主题的抓取与评分结果共享，各目标的发送记录独立保存。

## 安装与配置

需要 **AstrBot >=4.10.4、<5**，以及能主动发消息的 **OneBot v11 / aiocqhttp** 适配器，例如 NapCat。机器人应已能正常向目标群/好友发送消息。本插件没有使用 QQ 官方适配器的主动推送接口。

1. 在 AstrBot WebUI 的插件管理中选择从 Git 仓库安装，填入：

   ```text
   https://github.com/Hshevin/paper_bot
   ```

2. 在 AstrBot 的模型提供商页面配置你的服务商、模型、API 地址与密钥。可以同时配置 OpenAI 兼容接口和 Anthropic 提供商，之后在插件的“论文分析模型”下拉框切换。插件通过 AstrBot 调用模型，不另存 API 密钥。
3. 打开插件配置，在“共享研究主题目录”中新建主题，填写英文 ID、名称、详细研究兴趣、arXiv 分类等；参考下面的例子。
4. 在“群聊与私聊的独立订阅”中新建一项，填写完整目标会话标识、主题 ID 列表、间隔和启用开关。一个目标一条订阅，多个方向填入同一条的主题 ID 列表。
5. 保存配置，再打开“启用自动抓取和推送”。首次安装默认关闭、没有默认目标。保存后 AstrBot 会重载插件，之后按各订阅的间隔检查；无新推荐时不发送空消息。

目标格式是 `适配器实例ID:GroupMessage:群号` 或 `适配器实例ID:FriendMessage:QQ号`。其中实例 ID 是 AstrBot 平台配置里的实例 ID，**不一定叫 aiocqhttp**。管理员可在目标会话执行 `/paper_target` 取得完整值，或通过下面的绑定命令免于手动填写。聊天命令会同步写入同一份 WebUI 配置；已有配置页请刷新后再编辑。

## 完整配置示例

以下内容对应 WebUI 中的字段，不需要粘贴 JSON。分类/关键词决定去哪找，详细描述决定哪些论文值得推荐。

| WebUI 字段 | 示例 |
| --- | --- |
| 主题 ID | `rag` |
| 主题名称 | 可靠的检索增强生成 |
| 详细研究兴趣 | 关注通过检索、重排序和证据核验降低大模型事实错误的方法，希望看到可复现实验和引用可靠性评估。纯向量索引性能优化相关性较低。 |
| arXiv 分类 | `cs.CL`、`cs.AI`、`cs.IR` |
| 英文关键词与同义词 | `retrieval augmented generation`、`RAG`、`grounded generation` |
| 排除关键词 | 可留空；填写后是标题/摘要的硬排除条件 |
| 候选召回策略 | `broad` |
| 推荐分数阈值 | `75` |
| 订阅目标 | `/paper_target` 返回的完整值 |
| 此会话订阅的主题 ID | `rag` |
| 此会话推送间隔 | `60` 分钟 |

想让两个群关注同一领域的不同侧面，可以建立不同主题，例如 `rag-evaluation` 和 `rag-agents`，分别写研究描述和阈值，再分配给对应群。订阅列表中的主题 ID 要与主题目录一致，主题本身也需启用。

以下设置全部可通过 WebUI 修改：

- 各研究主题的描述、分类、关键词、排除词、阈值、召回模式、启用状态。
- 各群聊/私聊的目标、订阅方向、检查间隔（15–1440 分钟）、启用状态。
- 自动运行总开关、摘要模型、手动全文模型、首次回溯天数。
- 每轮每主题页数、全局分析篇数、每个目标最多推送篇数。

默认每轮每主题最多 3 页（每页 100 条），全局最多分析 20 篇，每个目标最多推送 5 篇。间隔从该目标上一次开始检查计算；后台每分钟检查到期订阅，正在执行的任务会串行完成，因此不是精确整点定时。

## 管理员命令

这些命令都只允许 **AstrBot 管理员** 使用，避免其他群成员更改收件人或消耗模型额度。若设置了不同的唤醒前缀，请使用宿主对应的前缀。

| 命令 | 作用 |
| --- | --- |
| `/paper_topics` | 查看研究主题 ID 和描述 |
| `/paper_target` | 查看当前群聊/私聊的完整会话标识 |
| `/paper_bind rag,agents 120` | 当前会话订阅指定方向，每 120 分钟检查；省略间隔为 60 分钟；写回 WebUI |
| `/paper_subscriptions` | 查看当前会话的订阅 |
| `/paper_unbind` | 在同一份 WebUI 配置中禁用当前会话订阅 |
| `/paper_run` | 立即处理所有启用的订阅并推送，忽略自动总开关和时间间隔 |
| `/paper_status` | 查看总开关、目标数量、最近结果与模型暂停状态 |
| `/paper_retry` | 解除失败分析队列的暂停；之后用 `/paper_run` 或等待下个间隔 |
| `/paper_fetch rag 2026-10-01 2026-10-07` | 抓取 UTC 日期范围（含起止日期）；只入库，随后 `/paper_run` 分析推送 |
| `/paper_read 2610.00001` | 对已入库论文手动下载 PDF、全文分析；报告只返回当前会话 |

`paper_fetch` 的手动范围不会改变自动订阅的时间游标；达到单轮页数限制时，重复相同命令可继续。全文精读不自动触发，可在 WebUI 选择独立模型。长论文分块分析，最多 15 次模型调用；拒绝大于 40 MiB、300 页、24 万字符或没有可提取文字的 PDF。全文提取存在图表、公式和扫描件的局限。

## 论文如何与方向匹配

1. **候选召回**：通过 arXiv 官方 Atom API 按分类和 UTC 提交日期查询。`broad` 在有分类时收集该分类的候选，不强制命中关键词；没有分类时使用关键词限定。`strict` 同时要求已填写的分类与关键词，并对标题/摘要做本地关键词过滤。
2. **排除与语义评分**：先应用明确的排除词。模型依据详细研究兴趣、标题和摘要给出 0–100 分、中文摘要、具体理由及摘要中的原文引文。分数表示相关性，不代表论文质量。英文关键词采用不区分大小写的词边界匹配；同义词需显式填写，没有自动扩词或向量索引。
3. **校验与存储**：模型必须返回可解析的数据，分数必须有效，引文必须确实存在于摘要中。格式错误或调用失败会暂停模型队列，不伪造分数。低分结果也保存，之后降低阈值可复用；改变研究描述等条件会重新评估。
4. **每目标排序推送**：仅合并该目标订阅方向中已完成分析、达到阈值、尚未发送的论文，按相关性降序，同分优先较新论文，最多推送配置数量。同一论文版本即使命中多个方向也只向该目标发送一次。

“最相关”指**当前已收集并分析的候选**中的排序，受分类、首次回溯范围和分析额度影响，并非扫描了整个 arXiv 后的全局最优。当候选增长快于处理额度时会积压；可缩小分类、选择 strict 模式或提高分析预算。新订阅已有共享主题时，可以收到该主题库中仍未向它推送的历史推荐。

## 数据、恢复与边界

- SQLite、PDF 缓存和手动精读结果保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_paper_bot/`，不写入插件源码目录；更新插件可保留状态。部署时持久化 AstrBot 的 data 目录。
- 只在整段冻结时间范围抓取成功后推进成功游标；分页和论文入库使用同一事务。超过 arXiv 单次 30,000 条上限会自动细分时间范围，未完成部分留待后续轮次。
- 自动增量抓取带 7 天重叠窗口，以缓解索引延迟；它不是历史版本的完整同步，超过重叠范围才公开的记录或旧论文新版本可能需要手动补抓。
- arXiv 请求串行，间隔至少 3.1 秒；429/网络错误保留进度，等下次订阅检查重试。错误消息不输出远端响应正文或密钥。
- 模型失败会暂停付费分析，检查提供商并执行 `/paper_retry`。已分析的推荐仍能推送。切换提供商不会强制重算已完成的评分。
- 成功消息按目标记录；失败目标可在下个间隔或 `/paper_run` 重试，其他已成功目标不会因它重发。若进程恰在消息发送后、保存记录前崩溃，或发送超时但平台实际已接收，重试可能重复；QQ 接口不提供端到端恰好一次保证。
- 为同一数据目录运行一个插件实例；这不是多主机分布式调度器。论文和模型输出仅作为文本，不能调用工具或执行指令。分析会把摘要（手动精读时为全文片段）发送给你选定的模型提供商。
- 原生 macOS 项目完整保留在 `legacy/macos/`，不参与插件加载；其本地论文库和设置不会自动导入插件，也不会修改已安装的 macOS 应用。

## 排查错误与日志来源

从 1.0.1 起，插件错误回复包含 `[Paper Bot]`、失败阶段、具体原因、修改建议和诊断号。配置错误定位到 WebUI 的第几项及字段，例如 `topics[0].categories` 表示第一个研究主题的分类，`subscriptions[1].topic_ids` 表示第二条订阅的主题 ID 列表。`cs. AI` 等分类点号两侧空白会自动规范化为 `cs.AI`。

运行 `/paper_status` 可查看最近一次错误；在 AstrBot 日志中搜索同一个诊断号，可以找到包含阶段、上下文和项目调用位置的插件诊断记录。arXiv 的 HTTP 状态、模型认证/限流错误以及 QQ 推送失败会分别显示。未知异常不展示原始响应、地址、密钥和局部变量，保留安全调用位置用于排错。若模型筛选已暂停，修正配置后先 `/paper_retry`，再 `/paper_run`。

AstrBot 的 `[Core] Prepare to send - 昵称/用户ID` 是宿主统一发送流程的日志；插件的普通命令回复也会经过这里，不能据此判断内容由模型生成。昵称和 ID 来自触发命令的用户，不是插件名或群号。插件自己的诊断由插件 logger 记录，具体标签随 AstrBot 版本显示为插件类别或名称；不修改核心发送日志。若出现重复日志，需要对照 QQ 实际消息和原始日志判断，不能仅凭相同日志行认定执行了两次。

## 开发验证

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/package.py
```

测试使用模拟 arXiv/LLM/QQ，覆盖订阅隔离、排名去重、不同频率和重启恢复、失败续传、WebUI 同源配置、权限与卸载取消、PDF 限制。另对照并测试 AstrBot v4.10.4 的真实 SDK；当前没有接入你的 QQ 实例或付费模型进行端到端测试。真实 arXiv 只读尝试收到 HTTP 429，未将其计为抓取成功。验证记录见 [docs/validation.md](docs/validation.md)。

本地生成的 `dist/astrbot_plugin_paper_bot.zip` 只含插件运行文件和说明，不含旧版原生应用、测试、数据库或密钥。
