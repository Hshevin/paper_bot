# AstrBot 插件设计

状态：已实施。日期：2026-10-31。

## 从原生应用迁移

保留原生代码到 legacy/macos，根目录改为 AstrBot 可安装入口。Python 核心与宿主解耦，不再依赖 macOS app 或外部 HTTP 桥。由 AstrBot 提供模型、消息平台、配置界面和插件生命周期。

## 订阅与方向

主题目录保存研究描述、检索条件与阈值；每个目标订阅若干主题并拥有自己的间隔。多个目标共享同一主题的候选/评分以节省费用，各自持有发送记录。全局额度限制模型分析和每目标推送量；仅处理当轮到期订阅所需主题。按目标跨主题排序，而非按主题依次占满推送额度。

配置唯一来源是 AstrBotConfig：WebUI 保存触发宿主重载；管理员绑定命令调用 save_config 同步到面板。SQLite 仅存任务状态、论文、模型结果和投递记录，不覆盖 WebUI 的订阅设置。

## 可靠性

API 使用冻结时间范围和分页检查点，入库与检查点原子提交；大窗口按时间细分但保留原终点。所有子窗口成功后才推进成功时间。轮次有预算上限，未完成工作跨轮继续。管理员日期抓取使用独立检查点。

论文按主题指纹和 arXiv ID 存储，较高版本替换旧版本并重新评分；阈值不参与指纹，调低阈值能复用低分。发送按目标、ID、版本去重，失败不落成功记录。远端发送与本地事务无法原子化，崩溃窗口存在至少一次投递的重复风险。

插件仅支持单实例调度，SQLite WAL 保证本地事务持久性，不声称跨实例调度排他。运行锁避免自动任务、手动范围抓取和全文精读并发。卸载取消并等待所有操作后关闭会话和数据库。

## 内容与模型边界

默认分类宽召回，详细研究描述负责语义筛选；可选 strict 降低候选成本。模型评分必须具备有效 JSON 和可核对的摘要原文依据。错误不会被替换为中性分数；失败暂停后由管理员恢复。自动流程只使用摘要，全文仅手动调用；所有模型输出仅进入纯文本消息，不作为命令或工具参数执行。
